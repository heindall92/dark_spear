Inyección SQL en endpoint de autenticación

Exportar PDF Asignar Remediación

Descripción técnica

Se identificó una vulnerabilidad de inyección SQL basada en errores en el parámetro username del endpoint /api/v1/auth/login. La entrada no se parametriza; el backend habla con PostgreSQL.

Prueba de concepto

La solicitud de verificación está en el vault del engagement. Aquí solo el envoltorio HTTP, sin payload.

HTTP Request · redactado 
POST /api/v1/auth/login HTTP/1.1
Host: api.internal
Content-Type: application/json

{
    "username": "[redacted — vault]",
    "password": "[redacted]"
}

Pasos de remediación

  1. Consultas preparadas: no concatenar cadenas. Usar ORM o parámetros nativos.
  2. Validación de entrada: allowlist en username.
  3. Mínimo privilegio: la cuenta de la app no debe tocar esquemas de sistema.

Ejemplo corregido (Node.js / pg)

const query = 'SELECT * FROM users WHERE username = $1';
const values = [req.body.username];
const res = await db.query(query, values);

Evidencia

Capturas del engagement. El detalle explotable vive en el vault; aquí el envoltorio.

Impacto al negocio

La explotación permite la exfiltración de la base de datos: credenciales, PII de clientes y datos financieros. En ciertas configuraciones, el mismo defecto puede escalar a compromiso del servidor de base de datos.

Causa raíz

  • Falta de validación de entrada en el servidor.
  • Consultas SQL por concatenación en lugar de ORM o parámetros.
  • Excepciones que filtran mensajes del motor al cliente.
